# 规则版本与冲突处理

## 当前版本

- 工作流版本：`0.3.0`
- 最新规则生效日期：`2026-08-27`
- 根入口：仓库根目录 `AGENTS.md`
- 公开规则与数值配置：`config/workflow.yml`
- 可选本机覆盖：`config/workflow.local.yml`，仅限项目根目录和 Python 路径

任何代理或协作者进入仓库后必须先读根入口，再由 `SKILL.md` 路由到专题规范。不得直接从某个旧文档、历史聊天或文件修改时间推断当前规则。

## 冲突顺序

发生冲突时依次采用：

1. 用户在当前任务中的最新明确要求；
2. 题目原文、官方附件和提交规范；
3. 当前项目经过实际运行或核验的事实；
4. `config/workflow.yml` 中当前版本的数值规则；仅机器相关字段采用本机覆盖；
5. 与任务直接对应的专题规范；
6. 根入口和总览中的通用默认值；
7. 更早版本、历史记录和一般经验。

同一层级只有在规则明确标注生效日期或版本号时才采用较新者。文件名中的“最终”“最新版”和操作系统修改时间不能单独证明版本优先级。

## 本机覆盖边界

`config/workflow.local.yml` 从 `config/workflow.local.example.yml` 复制生成，并由 `.gitignore` 排除。它的优先级只适用于以下字段：

- `project.default_root`：本机新项目的默认根目录；
- `python.preferred_executable`：本机固定 Python 解释器的绝对路径。

本机覆盖不得定义版本、生效日期、页面预算、数值精度、建模规则、验证规则或发布权限。上述内容即使误写入本机文件也不产生规则效力。运行 Python 前使用 `scripts/get_workflow_python.ps1` 解析有效路径；文件缺失、仍为占位符、不是绝对路径或目标不存在时必须停止。

## 0.3.0 对 0.2.0 的替换

| 主题 | 0.2.0 规则 | 0.3.0 当前规则 |
|---|---|---|
| 数据预处理 | 记录原因、公式和受影响记录数 | 按“问题—影响—识别依据—处理动作—样本变化—验证证据”形成完整依据链 |
| 模型表达 | 解释公式和相对基线收益 | 每次引入模型还必须说明如何建立、为何选用、相对前一方法的不足补偿和可验证优势 |
| 指标与阈值 | 报告定义和尺度 | 所有人为阈值必须说明来源、与决策的关系和敏感性；数据驱动阈值只能在训练数据内确定 |
| 模型验证 | 建立正向验证证据链 | 明确区分模型选择、假设诊断和敏感性分析，并完成与模型类型匹配的假设检验或诊断 |
| 合理性 | 使用样本外、残差或稳定性证据 | 每问分别论证数据合理性、模型合理性和结果合理性，不能用一句“模型合理”概括 |
| 摘要 | 写模型与算法建立过程、结果和验证 | 进一步概括模型如何建立、为何选择及其优势；模型算法与核心结论可突出，摘要加粗区域不超过 4 处 |
| 全文结尾 | 简要说明应用与价值 | 不足与改进方向集中写 3 至 4 行，不在各问正文中反复使用防御性语言 |

## 0.2.0 对更早规则的替换

| 主题 | 旧规则 | 当前规则 |
|---|---|---|
| 三问题正文 | 每问不超过 8.33 页 | 每问 7.33 至 8 页 |
| 四问题正文 | 每问不超过 6.25 页 | 第一问 5.5 至 6.25 页；后三问各 5.5 至 5.75 页 |
| 五问题正文 | 每问不超过 5 页 | 第一问 4.4 至 5.25 页；后四问各 4.4 至 4.75 页 |
| 摘要 | 每问尽量 6 行 | 前言 3 至 4 行；三问时每问约 8 行，四问时每问约 6 行，五问时每问约 5 行 |
| 表格 | 居中、约 1.25 倍行距 | 继续居中；LaTeX 全文表格统一 `\zihao{-5}`，内容尽量单行并优先合理加宽 |
| 结论位置 | 每问末尾单独结论 | 直接结论放入本问模型结果部分，不加装饰性边框 |
| 随机种子 | 记录以便复现 | 仍在代码和复现记录中保存，但论文和图表不展示具体取值 |
| 可视化 | 统一风格并解释图表 | 在此基础上增加逐问图表规划、流程图、建模示意图、必要动画、`2 x 2` 典型时刻图和迭代证据 |
| 模型表达 | 说明模型并验证结果 | 每个重要公式逐式解释；决定结论的关键条件必须证明；优化模型优先用大括号统一表示目标与约束 |
| 模型假设 | 简洁且有现实意义 | 继续简洁，但题目已知条件一律不得列为假设 |

## 记录新规则

新增规则时必须同时说明：来源、生效日期、解决的问题、适用范围、验证方式，以及它替换了哪条旧规则。稳定的数值写入 `config/workflow.yml`，详细方法写入专题规范，变更摘要写入 `CHANGELOG.md`。不得在多个文件中保存互相独立、无法判定优先级的数值副本。
