# 验证与交付规范

## 1. 数据与代码复现

- 从干净入口运行主代码，不依赖交互式会话中的残留变量；
- 记录 Python 版本、关键库版本、随机种子和输入文件；随机种子值只进入复现记录，不进入论文和图表；
- 检查所有输出文件确实由当前代码生成；
- 核对排除记录、样本量、分组数、优化搜索域和约束；
- 不联网安装库，配置的解释器缺失时停止并报告。

## 2. 模型验证

根据问题选择样本外预测、留一、留组、时间切分、空间切分、Bootstrap、敏感性或扰动分析。检查残差结构、异常点影响、边界预测和结论方向。拟合优度接近理论上限时完成专项复核并保留记录。

模型选择、模型假设诊断和敏感性分析必须分开记录。模型选择说明候选模型及统一评价口径；模型诊断检查最终结构的统计或算法前提；敏感性分析改变数据口径、阈值或参数。三者不能相互替代。

线性或混合效应模型至少核对固定效应、随机效应必要性、残差结构、方差稳定性、正态性和异常对象影响；分类模型至少核对区分能力、校准、多重共线性和阈值稳定性；优化或仿真模型至少核对约束可行性、终止或收敛、搜索域覆盖和扰动稳定性。只报告实际运行的诊断，不得虚构检验结果。

验证文字必须与实际执行的方法一致。“结果合理”不是验证方法；应写清使用了什么数据、指标和对照，以及它如何支持主要结论。

关键证明属于结果成立的前置验证。逐问检查：最终判据是否有推导，推导是必要条件、充分条件还是充要条件，离散实现是否覆盖连续定义，边界与退化情形是否处理，代码判定是否与论文公式一致。证明记录不完整时不得仅凭数值图宣称结论成立。

## 3. 数字一致性

建立结果核验表，逐项比对：

- 代码控制台或结果文件；
- Excel 表格；
- 图中标注；
- 正文结果；
- 摘要和结论；
- 附录或提交附件。

核对数值、单位、正负号、百分比尺度、四舍五入和约束条件。同一指标出现多个版本时追溯生成脚本和时间，不凭感觉选择。

## 4. 文档与版面

最终 Word 或 LaTeX 必须渲染后逐页检查：

- 实际页数是否符合预算；
- 标题、正文、公式、图表和表注是否重叠或截断；
- 表格是否溢出或贴边；
- 图片、中文字体和符号是否缺失；
- 图表编号、公式编号和交叉引用是否正确；
- 是否存在大面积空白、孤行、错误分页或重复内容。
- 各问实际正文页数是否落在当前配置的最小值和最大值之间；
- 摘要前言及各问段落是否符合当前行数预算；
- 结论是否位于模型结果部分且未使用装饰性边框；
- 表格字号是否统一为 `\zihao{-5}`，内容是否出现裁切或过度压缩。

结构检查、编译成功或无报错都不能代替视觉检查。

## 5. 内容扫描

检查以下问题：

- 数据预处理段缺失或与代码不一致；
- 数据处理没有说明问题、影响、识别依据、处理动作、样本变化和验证证据；
- 结论仅有口语化趋势，没有专业统计判断；
- 模型或算法突然出现，没有说明如何建立、为何选用及相对优势；
- 自定义指标或人为阈值没有来源、与决策的关系或敏感性分析；
- 数据驱动阈值利用验证数据反向调节，造成信息泄漏；
- 复杂模型没有相对简单基线的收益证据；
- 用 AIC、交叉验证或敏感性分析代替模型假设诊断；
- 未分别说明数据、模型和结果合理性的具体证据；
- 近完美拟合未检查泄漏或过拟合；
- 防御性语言替代合理性验证；
- 一段加粗超过 5 处或整句连续加粗；
- 摘要没有直接回答题目；
- 摘要只写模型名称，没有概括如何建立、为何选用及其优势；
- 摘要加粗区域超过 4 处；
- 把计划、预测或外推写成已完成实验。
- 题目已知条件被误列为模型假设；
- 关键公式没有说明建模对象和用途；
- 决定结论的遮蔽、覆盖、可行性或极值条件没有证明；
- 论文或图表展示了随机种子的具体取值；
- 图表没有正文引出或没有紧随分析；
- 动态过程只提供动画而没有论文可读的典型时刻静态图。

## 6. 交付包

交付包按用户要求选取以下内容，不默认全部打包：

- 最终论文源文件和可打开的最终稿；
- 运行入口与必要代码；
- 中文命名的结果表和高分辨率图表；
- 可编辑的流程图或建模示意图源文件，以及必要的动画支撑材料；
- 数据说明、环境说明和复现步骤；
- 验证记录与仍未解决的问题。

只对关键原始数据、最终稿或版本易混淆的交付文件计算 SHA256。交付后重新打开最终文件并核对数量、大小和关键内容。

## 7. Git 与发布

提交前逐项查看 `git status --short` 和差异，运行仓库校验并阅读发布边界。未明确远程仓库、可见性和发布授权时，只保留本地修改或本地提交，不推送到 GitHub。
