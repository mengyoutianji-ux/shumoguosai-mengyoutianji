# 流程图与建模示意图规范

## 1. 两类图的职责

- 流程图呈现一整问或整道题的逻辑：输入、模型、求解、验证、输出和必要反馈。
- 建模示意图呈现对象、坐标系、几何关系、运动方向、区域边界、视线或变量定义，可使用二维或三维视图。

流程图回答“如何求解”，示意图回答“模型描述什么”。二者均不能替代公式推导和关键证明。

## 2. 逐问规划

非纯数据分析问题原则上每问至少考虑一张可编辑的 draw.io 流程图或建模示意图。纯数据分析问题只有在流程确实复杂、图能减少文字负担时才添加。最终是否进入论文由 `图表规划表.csv` 中的论断、篇幅和证据价值决定，不机械追求每问同样数量。

一张逐问流程图通常包括：

1. 题面输入与核验；
2. 解释选择和模型假设；
3. 核心变量、目标与约束；
4. 模型方程与关键判据；
5. 求解或搜索过程；
6. 结果输出；
7. 证明、敏感性或其他验证；
8. 未通过验证时返回的具体步骤。

## 3. 示意图内容

根据题目选择必要元素：

- 坐标原点、坐标轴、方向和单位；
- 对象外形、关键点、边界、截面和尺度；
- 运动轨迹、速度或力的方向；
- 视线、覆盖域、可行域和临界位置；
- 与公式一致的符号；
- 需要对比的局部放大或不同视角。

没有数据含义的阴影、渐变或装饰不进入图中。三维图需要同时保证深度关系可辨、关键对象无遮挡，必要时配二维截面图。

## 4. draw.io 与导出要求

- 保留未压缩的 `.drawio` 原生 XML，节点和文字可以继续编辑；
- 同时导出 SVG；论文需要位图时再导出至少 300 dpi 的 PNG；
- 文件使用中文且简洁，如 `问题二_优化流程.drawio`、`问题一_遮蔽几何.svg`；
- 图内不放与论文 `\caption{}` 重复的总标题；
- 同一论文统一字体、线宽、箭头、色义和节点层级；
- 导出后分别验证源文件可解析、SVG 非空、文字未裁切、箭头连接正确和论文尺寸下可读。
