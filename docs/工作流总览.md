# 数学建模工作流总览

## 0. 确定任务边界

先确认题目数量、交付格式、截止时间、允许使用的工具和现有材料。将用户明确要求、题目硬约束和仓库默认规则分开记录；发生冲突时，按“用户最新要求—题目原文—经验证项目事实—仓库默认值”的顺序处理。

## 1. 材料清点与去重

建立材料清单，记录文件路径、类型、用途、可读状态、来源和版本。对同一问题的多份草稿或结果先比较内容和日期，再决定合并；不得仅依据文件名认定最新版。无法读取或来源不明的材料进入“未解决问题”，不能作为结论依据。

## 2. 题意拆解与指标定义

对每一问分别写明：输入数据、输出目标、约束条件、评价指标、变量关系和需要给出的最终结论。若题目只给宽泛方向，先建立研究问题和判定标准，再开始建模。

## 3. 数据核验与预处理

检查样本量、字段、类型、单位、编码、缺失、重复、异常、时间或空间范围及类别水平。所有删除、插补、变换、标准化和派生指标都要记录原因、公式和受影响记录数。正文每问第一段用 3 至 4 行准确概括实际执行的预处理，不得写不存在的步骤。

## 4. 探索性分析

使用描述统计、分组比较和必要图表确认数据结构、量级、趋势、异常点和可能的非线性。探索图用于提出候选关系，不直接替代统计检验或最终模型。发现数据质量问题时先回到第 3 步处理。

## 5. 模型建立与选择

先建立可解释的基线模型，再根据题目需要增加非线性、随机效应、空间结构、优化或仿真。候选模型采用统一的数据划分和评价口径比较。复杂模型必须证明其相对简单模型带来了实质性收益。

## 6. 求解与结果整理

保存可复现代码、参数、随机种子、软件版本和结果表。计算结果默认保留四位小数，单位必须统一。优化题写清搜索域、约束、步长或求解器终止条件；表述为“模型推荐方案”时，区分模型预测与实测结果。

## 7. 关系结论与模型验证

关系分析必须给出方向、强弱、显著性或非单调结构，并说明使用的指标。验证应围绕题目和模型构建证据链，包括样本外预测、残差诊断、方向一致性、稳定性、敏感性或合理的对照分析。拟合优度接近理论上限时执行专项复核。

## 8. 图表与表格制作

图表服务于结论而非装饰。统一配色、字体、线宽、图例和注释，确保范围、误差带和标注与数据一致。表格设置合适列宽和内边距，避免内容贴边或溢出。正文必须引用并解释每个保留的核心图表。

## 9. 论文写作

摘要按每问 3 至 4 个重点压缩模型、结果和验证；正文按“目标—预处理—模型—求解—结果—验证—结论”组织。先合并重复材料，再按题目数量控制篇幅。语言简洁、专业、连贯，不使用防御性语言回避验证。

## 10. 一致性与版面检查

核对代码输出、Excel、图表、正文、摘要和附件中的关键数字、单位、符号及精度。最终 Word 或 LaTeX 必须渲染后逐页检查，确认无空白页、截断、重叠、表格溢出、错误引用和缺失字符。

## 11. 交付与版本管理

交付目录仅保留必要成果、复现代码、数据说明和验证记录。只在关键原始数据或最终交付物上进行哈希校验。提交 Git 前执行发布边界检查，确保没有原始赛题附件、未公开论文、个人信息、凭据和大型中间产物。
