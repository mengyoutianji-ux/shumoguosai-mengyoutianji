# 数学建模工作流总览

当前规则版本、冲突顺序和旧规则替换关系见 [规则版本与冲突处理](规则版本与冲突处理.md)。进入仓库后必须从根目录 `AGENTS.md` 开始，再由技能入口路由到本总览和专题规范。

## 0. 确定任务边界

先确认题目数量、交付格式、截止时间、允许使用的工具和现有材料。将用户明确要求、题目硬约束、经验证项目事实和仓库默认规则分开记录；发生冲突时按根入口和版本规范处理。

## 1. 材料清点与去重

建立材料清单，记录文件路径、类型、用途、可读状态、来源和版本。阅读全部材料，尤其是题目原文和正式附件；对同一问题的多份草稿或结果先比较内容、明确版本号和生效日期，再决定合并。不得仅依据文件名或文件修改时间认定最新版。无法读取、来源不明或会改变数学解释的疑问进入“未解决问题”；阻塞性疑问应先报告，再开始建模。

## 2. 题意拆解与指标定义

对每一问分别写明：题目原文要求、输入数据、输出目标、约束条件、评价指标、变量关系、解释候选和需要给出的最终结论。若存在多种合理解释且会改变模型或结果，列出差异和影响并等待用户选择；用户选定后记录该选择，并为关键条件建立证明任务。

## 3. 数据核验与预处理

检查样本量、字段、类型、单位、编码、缺失、重复、异常、时间或空间范围及类别水平。所有删除、插补、变换、标准化和派生指标都要记录原因、公式和受影响记录数。正文每问第一段用 3 至 4 行准确概括实际执行的预处理，不得写不存在的步骤。

## 4. 探索性分析

使用描述统计、分组比较和必要图表确认数据结构、量级、趋势、异常点和可能的非线性。探索图用于提出候选关系，不直接替代统计检验或最终模型。发现数据质量问题时先回到第 3 步处理。

## 5. 模型建立与选择

先建立可解释的基线模型，再根据题目需要增加非线性、随机效应、空间结构、优化或仿真。候选模型采用统一的数据划分和评价口径比较。复杂模型必须证明其相对简单模型带来了实质性收益。

## 6. 求解与结果整理

保存可复现代码、参数、随机种子、软件版本和结果表。代码保存在 `03_模型与代码`，并固定使用配置中的 Python 解释器执行。随机种子保留在复现记录中，不进入论文和图表。计算结果默认保留四位小数，单位必须统一。优化题写清搜索域、约束、步长或求解器终止条件；表述为“模型推荐方案”时，区分模型预测与实测结果。

## 7. 关系结论与模型验证

关系分析必须给出方向、强弱、显著性或非单调结构，并说明使用的指标。验证应围绕题目和模型构建证据链，包括样本外预测、残差诊断、方向一致性、稳定性、敏感性或合理的对照分析。拟合优度接近理论上限时执行专项复核。

## 8. 图表与表格制作

先建立逐问图表规划，再制作流程图、建模示意图、结果图和验证图。时间相关模型可生成动态图作为支撑材料，并从具有数学含义的时刻选取 `2 x 2` 四联图进入论文。图表服务于结论而非装饰；统一配色、字体、线宽、图例和注释，确保范围、误差带和标注与数据一致。正文按“引出—呈现—分析”引用每个核心图表。

## 9. 论文写作

摘要前言控制为 3 至 4 行，每问按题目数量使用配置中的行数预算，并保留 3 至 4 个重点，覆盖模型、结果和验证。正文按“目标—输入核验—模型与逐式解释—关键证明—求解—结果与逐图分析—验证—直接结论”组织。先合并重复材料，再按当前版本的题目数量和问题序号控制篇幅。语言简洁、专业、可理解，不使用防御性语言回避验证。

## 10. 一致性与版面检查

核对代码输出、Excel、图表、正文、摘要和附件中的关键数字、单位、符号及精度。最终 Word 或 LaTeX 必须渲染后逐页检查，确认无空白页、截断、重叠、表格溢出、错误引用和缺失字符。

## 11. 交付与版本管理

交付目录仅保留必要成果、复现代码、数据说明和验证记录。只在关键原始数据或最终交付物上进行哈希校验。提交 Git 前执行发布边界检查，确保没有原始赛题附件、未公开论文、个人信息、凭据和大型中间产物。
