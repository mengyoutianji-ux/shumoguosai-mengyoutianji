# 数学建模工作流总览

当前规则版本、冲突顺序和旧规则替换关系见 [规则版本与冲突处理](规则版本与冲突处理.md)。进入仓库后必须从根目录 `AGENTS.md` 开始，再由技能入口路由到本总览和专题规范。公开规则读取 `config/workflow.yml`；若存在被 Git 忽略的 `config/workflow.local.yml`，仅以其中的项目根目录和 Python 路径覆盖对应机器字段。

## 0. 确定任务边界

先确认题目数量、交付格式、截止时间、允许使用的工具和现有材料。将用户明确要求、题目硬约束、经验证项目事实和仓库默认规则分开记录；发生冲突时按根入口和版本规范处理。

## 1. 材料清点与去重

建立材料清单，记录文件路径、类型、用途、可读状态、来源和版本。阅读全部材料，尤其是题目原文和正式附件；对同一问题的多份草稿或结果先比较内容、明确版本号和生效日期，再决定合并。不得仅依据文件名或文件修改时间认定最新版。无法读取、来源不明或会改变数学解释的疑问进入“未解决问题”；阻塞性疑问应先报告，再开始建模。

## 2. 题意拆解与指标定义

对每一问分别写明：题目原文要求、输入数据、输出目标、约束条件、评价指标、变量关系、解释候选和需要给出的最终结论。若存在多种合理解释且会改变模型或结果，列出差异和影响并等待用户选择；用户选定后记录该选择，并为关键条件建立证明任务。

## 3. 数据核验与预处理

检查样本量、字段、类型、单位、编码、缺失、重复、异常、时间或空间范围及类别水平。每项删除、插补、校正、变换、标准化和派生指标都按“数据问题—潜在影响—识别依据—处理动作—样本变化—验证证据”记录。可以可靠恢复的数据才校正；无法判断正确字段的逻辑冲突记录原则上删除。正文每问第一段用 3 至 4 行说明为什么必须预处理、主要规则和有效样本，不得写不存在的步骤。

## 4. 探索性分析

使用描述统计、分组比较和必要图表确认数据结构、量级、趋势、异常点和可能的非线性。探索图用于提出候选关系，不直接替代统计检验或最终模型。发现数据质量问题时先回到第 3 步处理。

## 5. 模型建立与选择

先建立可解释的基线模型，再根据题目需要增加非线性、随机效应、空间结构、优化或仿真。每次引入新模型前说明前一方法仍缺少什么、当前模型如何建立、为什么适合数据以及相对基线具有什么可验证优势。候选模型采用统一的数据划分和评价口径比较。自定义指标和人为阈值必须说明来源、与决策的关系和敏感性；数据驱动阈值只能在训练数据或训练折内确定。

## 6. 求解与结果整理

保存可复现代码、参数、随机种子、软件版本和结果表。代码保存在 `03_模型与代码`，并使用 `scripts/get_workflow_python.ps1` 解析和验证固定 Python 解释器后执行。随机种子保留在复现记录中，不进入论文和图表。计算结果默认保留四位小数，单位必须统一。优化题写清搜索域、约束、步长或求解器终止条件；表述为“模型推荐方案”时，区分模型预测与实测结果。

## 7. 关系结论与模型验证

关系分析必须给出方向、强弱、显著性或非单调结构，并说明使用的指标。模型选择、模型假设诊断和敏感性分析分别回答候选模型比较、统计前提成立和结论稳定三个不同问题，不得相互替代。验证应围绕题目构建数据合理性、模型合理性和结果合理性三层证据链，包括样本外预测、残差与随机效应诊断、方向一致性、稳定性、敏感性或合理对照。拟合优度接近理论上限时执行专项复核。

## 8. 图表与表格制作

先建立逐问图表规划，再制作流程图、建模示意图、结果图和验证图。时间相关模型可生成动态图作为支撑材料，并从具有数学含义的时刻选取 `2 x 2` 四联图进入论文。图表服务于结论而非装饰；统一配色、字体、线宽、图例和注释，确保范围、误差带和标注与数据一致。正文按“引出—呈现—分析”引用每个核心图表。

## 9. 论文写作

摘要前言控制为 3 至 4 行，每问按题目数量使用配置中的行数预算，并按“建模对象与难点—模型如何建立、为何选用及其优势—关键结果—合理性证据”组织。正文按“目标—输入核验—方法过渡—模型与逐式解释—关键证明—求解—假设诊断—结果与逐图分析—敏感性—直接结论”组织。删除“为落实题目要求”“下面报告结果”等过程性套话。全文结尾的不足与改进方向集中写 3 至 4 行，不在各问正文中反复使用防御性语言。

## 10. 一致性与版面检查

核对代码输出、Excel、图表、正文、摘要和附件中的关键数字、单位、符号及精度。最终 Word 或 LaTeX 必须渲染后逐页检查，确认无空白页、截断、重叠、表格溢出、错误引用和缺失字符。

## 11. 交付与版本管理

交付目录仅保留必要成果、复现代码、数据说明和验证记录。只在关键原始数据或最终交付物上进行哈希校验。提交 Git 前执行发布边界检查，确保没有原始赛题附件、未公开论文、个人信息、凭据和大型中间产物。
