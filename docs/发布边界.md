# 发布边界

本仓库可以公开或私有托管工作流规则，但具体竞赛项目默认视为非公开材料。

## 可以进入工作流仓库

- 通用规则、检查清单和项目空白模板；
- 不含项目数据的示例结构；
- 标准库实现的环境检查和仓库校验脚本；
- GitHub Issue、PR 和自动校验配置；
- 经确认可公开的通用经验。
- 自行制作且不含具体赛题数据的流程图、建模示意图模板和版式模板。

## 默认不得进入仓库

- 赛题附件、原始数据、录音、视频、截图和未公开论文；
- 含姓名、学号、联系方式、账号或地理隐私的信息；
- `.env`、访问令牌、Cookie、证书、数据库连接串和本地凭据；
- `config/workflow.local.yml` 及其中的本机绝对路径；
- 大型模型、虚拟环境、软件缓存、编译中间文件和临时导出；
- 未经验证的成绩、获奖、发表、部署或实验完成声明；
- 未取得再分发许可的优秀论文全文、论文截图或从其图件直接裁剪的素材；
- 仅适用于某一道题的绝对路径、真实样本值和内部讨论记录。

## 发布前检查

1. 运行 `git status --short`，逐项确认所有待提交文件。
2. 运行 `scripts/validate_repository.py`。
3. 搜索令牌、密码、邮箱、手机号、绝对用户目录和项目专有名称，并确认 `config/workflow.local.yml` 仍被 Git 忽略。
4. 确认模板中的示例值不可能被误认为真实结果。
5. 未明确远程仓库和可见性时，不执行推送；包含内部工作习惯时优先使用私有仓库。
6. 引用优秀论文时优先记录官方来源、题目、年份和借鉴点；除非确认许可，不把 PDF 或截图复制到工作流仓库。
